# CodeGalaxy 🌌

**Understand every line. See every change.**

CodeGalaxy is an educational code-execution visualizer. It helps learners see how variables, loops, assignments, and program output change as a program runs.

## MVP features

- Editable C source panel with a sample program
- Step forward, step backward, play/pause, and reset controls
- Current-line highlighting and an execution timeline
- Variable inspector and an illustrative stack/memory panel
- Program output panel and basic trace explanations
- Separate **Run trace** and **Run C** actions
- Real C compile/run through an isolated Piston execution service, including compiler diagnostics and optional standard input
- Request size limits, per-IP rate limiting, and bounded execution time in the API service
- Small educational trace engine for integer declarations, simple arithmetic assignments, increment/decrement, braced `while` loops, and simple `printf` calls

## Important limitation

The **Run trace** button is still an educational tracer and supports only a small subset of C. Use **Run C** for real compilation and execution through the separately configured Piston sandbox. The visual variable/memory timeline is currently generated by the educational tracer; it is not yet a source-level trace of the real process. The memory addresses shown are illustrative, not actual process addresses.

## Run locally

Requires Node.js 20 or newer.

```bash
npm install
npm run dev
```

Create a production build:

```bash
npm run build
npm run preview
```

## Enable real C execution locally (Piston)

The browser calls a small API service, which forwards requests to a **self-hosted Piston sandbox**. Do not point this API at an unsandboxed compiler or execute submitted source directly on the API host.

1. Start your own Piston instance by following the official [Piston setup instructions](https://github.com/engineer-man/piston#installation). The default local endpoint is `http://localhost:2000/api/v2/execute`.
2. In a second terminal, install and start the API service:

   ```bash
   cd server
   cp .env.example .env
   npm install
   npm run dev
   ```

3. In the project root, copy `.env.example` to `.env.local` (Vite reads this file) and keep `VITE_EXECUTION_API_URL=http://localhost:8787/api/execute`.
4. Start the frontend with `npm run dev`. The API health check is available at `http://localhost:8787/health`.

For deployment, set `PISTON_API_URL` to your private Piston service URL and `FRONTEND_ORIGIN` to the exact frontend origin. Keep the sandbox private to the API network; never expose its Docker host or execution worker directly to the public internet. The API limits source to 20,000 characters, input to 8,000 characters, and requests to 20 per minute per IP. Piston applies the compile/run resource limits in the request as well. Tune limits to match your deployment capacity.

## Deploy C execution on Cloudflare

A Cloudflare Worker + disposable Cloudflare Sandbox container implementation is available in [cloudflare-execution/README.md](cloudflare-execution/README.md). It uses Cloudflare Containers with GCC rather than a separately hosted Piston service.

Cloudflare Sandboxes require the Workers Paid plan. Deployment also requires Node.js 20+, Docker running locally, and authorizing Wrangler in your browser. Before public launch, configure the exact frontend origin and a Cloudflare rate-limiting rule for `POST /api/execute`. The integration uses the Cloudflare Sandbox SDK preview, so test the complete flow in your own account before production use.

## Roadmap

1. Add source-level stepping by instrumenting programs in the sandbox

## Security

Never execute arbitrary user-submitted code directly on a production server. A real compiler integration must run in a properly isolated sandbox with CPU, memory, filesystem, and execution-time limits.
